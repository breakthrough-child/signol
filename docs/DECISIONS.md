# Key technical decisions

Each entry: the decision, why, and what it costs.

1. **LLM for language, code for truth.** Quote verification, scoring, taint, calibration and the decision rules are plain code. *Why:* the hackathon asks for reasoning you can inspect; hallucinated quotes would destroy trust; deterministic code is testable and free. *Cost:* the fuzzy matcher and the weights are hand-tuned heuristics.
2. **Direct HTTP adapters instead of vendor SDKs.** `lib/llm` uses `fetch` for Groq (OpenAI-compatible) and Gemini. *Why:* full control over retry, `retry-after`, error classification and token logging; trivial to fake in tests; no SDK version drift. *Cost:* we maintain two small request/response mappers.
3. **Model IDs in configuration, defaults unverified.** *Why:* free-tier catalogues change; the provider documentation sites were unreachable while building, so we could not confirm IDs. *Cost:* a deployer may have to override a retired ID (documented in `.env.example`).
4. **Provider order with fallback on rate limit, error or invalid JSON; never wait long.** If a rate-limit window is longer than 15 s (a daily quota), fall back immediately instead of sleeping. *Why:* serverless requests are short and daily caps are common on free tiers.
5. **Resumable pipeline made of stored steps, driven by the browser.** One `pipeline_steps` row per (step, interview); each step is one ≤ 60 s request. *Why:* Vercel function limits, visible progress, resume-from-failure, and the user sees "retrying in Ns". *Cost:* an extra table (not in the original list) and a client-side loop. A 90 s staleness window prevents double-running a step that is still executing.
6. **Supabase anonymous auth + RLS everywhere, no service-role key.** Server routes use the caller's session (cookies via `@supabase/ssr`). *Why:* judges need no sign-up; a server compromise cannot read other users' data. *Cost:* cleared cookies lose access to projects; email magic link is not implemented (it was optional).
7. **Files go browser → Storage directly.** *Why:* Vercel's request body limit is far below the 25 MB audio limit. The API then reads the file as the user.
8. **Constraints in the database, not only in the UI.** Lock trigger on hypothesis/prediction, immutable decisions, owner checks on child inserts, share links through a `SECURITY DEFINER` function that returns only a frozen snapshot. *Why:* UI-only rules are decorative. *Cost:* behaviour is split between TS and SQL.
9. **Decision log is a frozen JSON snapshot.** Exports and the share page render it; they never recompute. *Why:* a decision log must not change when scores or prompts change later; also keeps the public RPC trivially safe.
10. **Statistics through a `stats_rows(p_all)` function.** `p_all` aggregates everyone but returns only durations and counts; no content, no ids. *Why:* `/stats` can show pooled time-saved numbers to judges without a service key.
11. **"Supports" for an interviewee = strong supporters outnumber strong counter-statements and weighted for > against.** Used for the prediction comparison. *Why:* simple, explainable, not fooled by weak promises. *Cost:* mixed interviews count as "not clearly".
12. **Top-3 selection is model-assisted but code-bounded.** The model chooses from code-ranked candidates and writes the "why"; invalid or missing picks are backfilled by code. *Why:* ranking evidence is where models are least reliable and where trust matters most.
13. **shadcn/ui as source, not CLI.** Components are written in shadcn's style (cva, tailwind-merge, `components.json`) without Radix. *Why:* the registry was not reachable; native `<details>`, radios and checkboxes give keyboard and screen-reader support for free.
14. **System fonts, no web fonts.** A serif display stack plus the system sans. *Why:* no build-time network dependency, faster first paint, still distinctive.
15. **Hand-annotated demo data compiled into the cache.** `seed/src/*.md` carry `{{type|rationale|quote}}` annotations; `scripts/build-seed.ts` strips them into plain transcripts and builds `demo.json`, failing if any quote does not verify with the app's own code. *Why:* we had no model access to produce a cache, and annotated sources keep the cache auditable. *Cost:* the cache is curated, not model output; it is labelled as cached and `npm run cache:demo` replaces it with a real run.
16. **Mock provider, fake HTTP LLM and a local Supabase shim.** The offline `mock` adapter is a keyword heuristic for UI development; the e2e fake speaks the Groq and Gemini wire formats; `scripts/local-stack` runs real Postgres with the real migrations behind a small implementation of the Supabase Auth, Storage and PostgREST subset we use. *Why:* no Docker, no keys and no outbound access in the build environment. *Cost:* the shim is not PostgREST; the RLS tests are written against the public Supabase API so they run unchanged against a real project.
17. **`--legacy-peer-deps`.** Some dev tools declare conflicting peer ranges against the newest React/Vite; production dependencies are unaffected.
18. **Seed transcripts are English with light Nigerian English phrasing.** Real-world Pidgin or code-switched transcripts are listed as a limitation instead of being faked.
